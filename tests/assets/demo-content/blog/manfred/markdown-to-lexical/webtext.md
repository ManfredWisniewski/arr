Spent the day on the seam between two text formats. The content repo speaks markdown — `webtext.md` files with YAML frontmatter. Payload's editor speaks Lexical — a JSON tree of nodes. The bridge is a `beforeValidate` hook: when a push sends `markdownRaw` and it differs from what is stored, the `content` field is regenerated by the Lexical markdown converter.

Two details made it work the way I wanted.

**The diff check.** Updates that carry no `markdownRaw` — or the same one — leave `content` untouched. That means an editor can fix a typo in the admin and the fix survives until the next real push changes the source. Manual edits lose to the source of truth, but only when the source of truth actually speaks.

**The extensions.** Heading anchors and link attributes are extracted before conversion and applied after — `{#my-anchor}` on a heading becomes a real anchor in the rendered HTML, and link targets like `{target="_blank"}` survive the trip through the editor format.

The raw markdown stays in the database next to the tree. Not because it is needed for rendering — because the next conversion needs it to know whether anything changed.
